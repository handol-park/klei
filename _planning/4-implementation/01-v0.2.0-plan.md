# Implementation Plan: v0.2.0 - vLLM Communication Channel

## Overview

This document provides a step-by-step implementation plan for v0.2.0, which focuses exclusively on replacing the HTTP/curl communication layer with Unix Domain Sockets and migrating from Ollama to vLLM.

**Status:** Milestones 1 & 2 Completed. Milestone 3 In Progress.

## Project Structure

```
core/
├── FFI/
│   ├── socket.h           # C header (DONE)
│   ├── socket.c           # C implementation (DONE)
│   ├── lean_glue.c        # Lean FFI glue code (DONE)
│   └── test_socket.c      # C-level test suite (DONE)
├── Klei/
│   ├── Communication/
│   │   ├── Socket.lean    # Lean FFI bindings (DONE)
│   │   └── Http.lean      # HTTP-over-UDS layer (IN PROGRESS)
│   ├── vLLM.lean          # vLLM client (PENDING)
│   ├── Ollama.lean        # HTTP/curl implementation
│   └── Backend.lean       # Backend abstraction (PENDING)
├── Main.lean              # REPL entry point
├── TestSocket.lean        # Lean FFI validation test (DONE)
├── Klei.lean              # Library root
└── lakefile.lean          # Lean build configuration (Updated to 4.26.0)
```

### Milestone 3: HTTP-over-UDS Layer [IN PROGRESS]

**Goal:** Implement minimal HTTP/1.1 client over Unix Domain Sockets

**Rationale:** Research confirmed that vLLM (via Uvicorn) speaks standard HTTP over UDS, not JSON-RPC.

#### Tasks

1.  **Write Http.lean**
    *   Define `HttpRequest` and `HttpResponse` structures.
    *   Implement `RequestBuilder`:
        *   Construct `POST /v1/... HTTP/1.1` lines.
        *   Add `Host` (dummy), `Content-Type`, `Content-Length` headers.
        *   Append JSON body.
    *   Implement `ResponseParser`:
        *   Parse status line (`HTTP/1.1 200 OK`).
        *   Parse headers (extract `Content-Length` or `Transfer-Encoding`).
        *   Read body based on length or chunked encoding.
    *   Location: `core/Klei/Communication/Http.lean`

2.  **Implement Chunked Transfer Decoding**
    *   vLLM streaming responses use `Transfer-Encoding: chunked`.
    *   Need parser for hex length markers and CRLF delimiters.

3.  **Write HTTP tests**
    *   Mock vLLM server (using `nc -lU` or Python `http.server` bound to UDS).
    *   Test full request/response cycle.
    *   Test large payloads.

**Acceptance Criteria:**
- Can send valid HTTP POST requests to vLLM via socket.
- Can parse HTTP 200 OK responses with JSON bodies.
- Can handle chunked encoding (for streaming).

### Milestone 4: vLLM Client Implementation

**Goal:** Create vLLM client using UDS protocol

#### Tasks

1. **Write vLLM.lean**
   - Define `GenerateParams` structure:
     - `prompt : String`
     - `max_tokens : Nat`
     - `temperature : Float`
     - `stream : Bool := false`
   - Implement `generate` function:
     - Construct HTTP POST request for `/v1/completions`
     - Call HTTP layer
     - Extract text from response body
   - Implement `chat` function (optional, for multi-turn):
     - Use `/v1/chat/completions` endpoint
     - Support messages array
   - Location: `core/Klei/vLLM.lean`

2. **Define vLLM API types**
   - Match OpenAI-compatible API format
   - `CompletionRequest`, `CompletionResponse`
   - `ChatRequest`, `ChatMessage`, `ChatResponse`
   - Derive JSON instances

3. **Add configuration**
   - Socket path from environment: `VLLM_SOCKET` (default: `/tmp/vllm.sock`)
   - Timeout from environment: `VLLM_TIMEOUT` (default: 30000ms)
   - Model name parameter (default: read from vLLM server)

4. **Error handling**
   - Connection failures → retry with backoff
   - Timeout errors → return clear message to user
   - Invalid responses → log and return error

**Acceptance Criteria:**
- vLLM client sends valid OpenAI API requests
- Responses parsed correctly
- Text extraction works
- Configuration via environment variables

### Milestone 5: Backend Abstraction

**Goal:** Create unified interface for Ollama and vLLM

#### Tasks

1. **Write Backend.lean**
   - Define `Backend` inductive type:
     ```lean
     inductive Backend where
       | ollama
       | vllm
     ```
   - Define `BackendAPI` structure class:
     ```lean
     structure BackendAPI where
       generate : String → IO (Except Error String)
       configure : IO Unit
     ```
   - Implement instances for Ollama and vLLM
   - Location: `core/Klei/Backend.lean`

2. **Add backend selection**
   - Read `KLEI_BACKEND` environment variable
   - Parse to `Backend` type
   - Default: `ollama` (for compatibility)
   - Function: `selectBackend : IO Backend`

3. **Unified API**
   - Single `generate` function that dispatches to backend
   - Hide implementation details from caller
   - Consistent error types

**Acceptance Criteria:**
- Both backends work through unified API
- Environment variable switching works
- Same REPL experience regardless of backend

### Milestone 7: vLLM Environment Setup

**Goal:** Integrate vLLM into Nix development environment

#### Tasks

1. **Update flake.nix**
   - Add `vllm` to build inputs (may need to package for Nix)
   - Alternative: Use Python with pip/uv to install vLLM
   - Add vLLM models directory: `export VLLM_MODELS="$PWD/.vllm/models"`
   - Set socket path: `export VLLM_SOCKET="/tmp/vllm.sock"`

2. **Create start-vllm helper**
   - Similar to `start-ollama`
   - Start vLLM server:
     ```bash
     vllm serve MODEL_NAME \
       --uvicorn-unix-socket /tmp/vllm.sock \
       --uvicorn-unix-socket-perms 0600 \
       --quantization awq \
       --dtype half \
       --max-model-len 32768 \
       --gpu-memory-utilization 0.90 \
       --enable-prefix-caching
     ```
   - Check if server is running (ping socket)
   - Download model if not present
   - Set restrictive socket permissions

3. **Model selection**
   - Start with smaller model for testing: `Qwen/Qwen2.5-7B-Instruct-AWQ`
   - Production model: `HuggingFaceH4/gpt-oss-20b-AWQ` or similar
   - Allow model override via environment: `VLLM_MODEL`

4. **Document setup**
   - Update README.md with vLLM setup instructions
   - Document model requirements
   - Add troubleshooting section

**Acceptance Criteria:**
- vLLM available in Nix shell
- `start-vllm` command works
- Socket created with correct permissions
- Model downloads and loads
- Server responds to requests
